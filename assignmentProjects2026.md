# Parallel stencil computations (Thu May 14)
Parallel stencil computations are a fundamental pattern in high-performance computing (HPC), used to solve partial differential equations (PDEs) numerically across structured grids. They involve iteratively updating grid points based on values from neighbouring points using a fixed pattern, known as a stencil. In this project the students need to select one or more stencil computations (e.g., cellular automata) and produce a parallel implementation in Java comparing it with parallel implementation in C++. The students should explore shared memory parallelism in addition to memory (cache) optimisations in this project.

# Optimising a Canny Edge Detection algorithm in cuTile (Fri May 15)
[cuTile](https://docs.nvidia.com/cuda/cutile-python/), developed by NVIDIA, the GPU company, is a domain specific language based on Python for parallel programming of NVIDIA GPUs. It aims to provide a Python-based programming environment for writing portable compute kernels across different NVIDA GPUs. It also avoids the need to use low-level programming of GPUs, e.g. with CUDA. cuTile kernels are GPU programs that are executed in parallel on a logical grid of blocks. In this project, you will implement a Canny Edge detection for images with it. Implement a version in Python without the use of cuTile and then optimise it by implementing as much of it with cuTile as possible. Measure the change in performance in every step and explore the parameters that lead to best performance. Try to apply the algorithm in real time to a stream of input images (video stream). Explain the scheduling and optimisation decisions in your report. **NOTE: cuTile needs an NVIDA graphics cards, so make sure at least one team member has such a card!**

# Implementing a parallel/concurrent garbage collector (Thu May 21)
Garbage collection (GC) plays a fundamental role in many programming languages -- that of collecting unused heap allocated objects. GC provides safety by preventing memory leaks. However, the usual (stop-the-world) GC approach is unsuited for high throughput and low latency applications. Hence, in this project we want to develop parallel GC. In this project, students will develop a parallel and/or concurrent GC for the C programming language. The students should compare their implementation with non-parallelised stop-the-world GC and non-GC based solutions for memory heavy applications. Some papers to begin with would be: [1] Lock-free parallel and concurrent garbage collection by mark&sweep (Gai et. al. 2007); [2] A Parallel, Real-Time Garbage Collector (Cheng et. al. 2000); [3] Krishnan et al. (2014) – Concurrent, Parallel Garbage Collection in Linear Time, etc.

# Accelerating machine learning on Rasberry Pi with an NPU (Fri May 22)
Neural Processing Units (NPUs) are part of modern processors and graphics cards. These units are designed for very power-efficient machine learning applications, with very high parallelism of simple and low precision operations. In fact, their low power consumption allows them to be embedded in small devices like phones or smart watches. In this project you will be given a Rasberry Pi 5 with an AI Kit (a small extension board) that contains such an NPU. Using this NPU (Hailo-8L) and the provided programming toolkit from the manufacturer Hailo [hailo.ai](https://hailo.ai), [on github](https://github.com/hailo-ai), you will implement a small machine learning application pipeline and measure its achieved performance. Compare the performance to the case where no NPU is used. The application must be non-trivial and developed by you, just implementing a small tutorial example or the output of an LLM is not sufficient. Explain in your report how your implemented machine learning application pipeline takes advantage of the NPU device.
